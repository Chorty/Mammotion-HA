## 1. FIX — defects that mislead or waste runs

### 1a. E-VIO scores heading-frame discontinuities 🚨 unfixed
`vio_not_live_throughout` checks `vio_state`, not continuity. On 2026-09-03 a
−166.47° VIO jump with `vio_state: 2` throughout was scored as −149.79 °/s while
the mower drove straight. **A frame jump inside a real step phase becomes a
number the criterion trusts.**

**Shape of the fix, to be PREDECLARED before implementation** (it changes when
the criterion refuses): refuse to score when a between-reading heading delta
exceeds what the commanded angular rate can physically produce over that dt —
with the bound derived from the now-measured rates (**−9.175 at angular 120,
−13.431 at 180, plus margin**), not invented. Emit a named reason
(`vio_heading_discontinuity`) so it is never silent.
⚠️ Validate against all banked runs: it must NOT refuse any of the six clean ones.

### 1b. Report subscription is never renewed (medium, fails closed)
A 23 s window rides one `RPT_START` for ~27 s un-renewed, while pymammotion's own
path renews every 8 s "below the device 10 s timeout". Both renewal sites are
dead during the probe's lease. It fails closed — a lapsed subscription starves
the feed and trips the stale-abort — so it **wastes a supervised run** rather than
being unsafe. Fix or document as a known cost before any long window.

### 1c. Review dimensions never verified
`evio-scoring-larger-n` and `regression-risk` have produced findings but never a
surviving verifier. `regression-risk` is the one that matters now: it asks
whether the constant and gate changes broke other callers.
⚠️ Run in small batches; salvage `journal.jsonl` incrementally.

## 2. CAPITALIZE — what the new measurements unlock, cheaply

### 2a. Retire the stale speed constants everywhere 🔑 free, offline
Sustained speeds are now measured (**300 → 0.223, 400 → 0.295 m/s**) and the
command/speed relation is **linear**, refuting the long-quoted "39% cut for a 25%
command cut". Grep the tree and docs for the old ramp-inclusive figures
(0.116, 0.191, 0.2482, 0.2616) and the non-linearity claim, and correct or
caveat each. **Several planning numbers elsewhere are built on them.**

### 2b. Record the rotation model as bounded, not fitted
`ω(400,120) ≈ −8.2`, `ω(300,120) = −9.175`, `ω(400,180) ≈ −11.8`,
`ω(300,180) = −13.431`. ⚠️ **Four points, n = 1 each, mechanism unexplained — do
NOT fit a law.** Record as a lookup with explicit uncertainty, and note the
~+12–13% linear-speed effect as *reproducible but unexplained*.

### 2c. Write down the two method lessons that keep repaying
- **Separate the ramp before sizing any window** (3 failures in 8 days; an 8 s
  average agreed with the extrapolation to 1.6% and was still wrong).
- **A phase length is part of the hypothesis** — copying `step_ms` from a run
  with a different purpose silently made a measurement impossible.

## 3. ADVANCE THE ACTUAL GOAL — click-to-path reliability

🔑 **This is where mower time should go, and it needs no new code.**

Current evidence is thin exactly where the goal lives:

| leg length | evidence |
| --- | --- |
| 3.0 m | **5 reached / 1 failed, n = 6** |
| 4.0 m | n = 1 (0.1023 m) |
| 5.0 m | n = 1 (0.10148 m) |
| 6.0 m | n = 1 (0.11440 m) |

**Feasibility is proven; RELIABILITY is not.** A landing population at the
accepted profile is what would let an operator "trust it without watching".

**Proposed, to be predeclared before any dispatch:** a repeat series at a single
length — **4.0 m is the right choice** (comfortably inside the 6.10 m cap, long
enough to exercise mid-drive correction, short enough for several runs per
session) — scoring landing distance, corrections used, and failure mode. Target
**n ≥ 5** at one length before adding others.
🔑 **Predeclare the pass criterion and the abort rule before the first run**, and
send `docs/accepted-profile.json` verbatim, verified key-by-key — the card
auto-splits above 3.85 m and would measure the splitter instead.

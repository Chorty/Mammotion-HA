## Why this `go` is not the shortcut that was rejected

The arc120 capture was explicitly **not** admitted (`docs/phase1b-arc-protocol-20260823.md`)
because both control dimensions would have moved at once with the outcome
already known. This run is different in kind, not just in result:

- **Registered first.** Duration (8000 ms), command (`linear 400, angular 180`
  — unchanged), minimum chord (0.15 m), required step count (3), pairing
  (START), and threshold (10 deg) were all written down before this capture
  existed, with two tests pinning that they cannot become a menu.
- **Driven fresh, after registration.** This is not a capture that already
  existed and happened to pass; it was run specifically to be scored against
  the already-committed rule.
- **The command is identical to the original plan.** `linear 400, angular 180`
  — only the window length changed, for the reason stated in the registration:
  a 4 s window cannot reliably clear 3 informative chords once the short

## What this does and does not authorize

✅ **Phase 1 telemetry feasibility is established under the repaired,
pre-registered criteria.** Position and heading telemetry sustain through an
8 s window at the cadence and accuracy the plan required.

🔒 **This is scoped, and the scope is explicit in the analyzer's own output:**
`"verdict_scope": "Phase 1 telemetry feasibility only; never authorizes Phase 2
or motion"`. A `go` here means the mower can be observed well enough to attempt
a closed-loop controller. It says nothing about whether such a controller is
safe, accurate, or worth building -- that is Phase 2 design work, not yet
started.

🔑 **Two things measured today remain true and still bound Phase 2 design:**

- Position and heading arrive as one ~1 Hz bundle
  (`docs/the-1hz-bundle-is-the-ceiling-20260822.md`) -- a controller can
  observe no faster than that, whatever it consumes.
- The pairing residual, alpha = -0.149 +- 0.043
  (`docs/codex-adjudication-20260823.md`), is unexplained and unmodelled. It
  costs ~7 mm per step and does not block this verdict, but it is not resolved
  by this run either.

⚠️ The prediction-error criterion remains **unimplemented and unadopted**. This
`go` rests on the repaired mirror criterion alone.
